# Security boundaries

The applications intentionally differ at twelve security boundaries. `app-fixed` imports no vulnerable code and has its own PDO connection, authentication, role/ownership checks, native prepared queries and MySQL database. Neither application's source nor Composer vendor tree is inside Apache's document root.

## Fixed controls

- Passwords use Argon2id through `password_hash` and `password_verify`, with random salts and a work factor. Successful logins upgrade older supported hashes. Registration cannot select roles, and profile updates accept only email/full_name.
- JWTs use externally configured random signing material. Configuration fails closed if the key is short or obviously repetitive. Validation pins HS256, issuer, audience, subject type, expiry, issue time, maximum lifetime and database role. Secrets are generated by `scripts/setup.php` and excluded from version control.
- Orders and profiles enforce ownership or an explicit admin exception. Staff has no admin-list permission. Login itself does not authorize access to another customer's objects.
- PDO disables emulated prepares and multiple statements. All fixed searches bind input. Database connections use utf8mb4; price columns use DECIMAL and checkout computes with integer cents.
- Feedback is stored verbatim but encoded using `htmlspecialchars(ENT_QUOTES | ENT_SUBSTITUTE)` when emitted into HTML. JavaScript UI rendering encodes dynamic text.
- Uploads allow actual PNG/JPEG/GIF content only, inspect extension and detected MIME, decode with GD, constrain byte size/dimensions and re-encode to PNG. Random filenames live outside the web root and are served by a constrained image controller with `nosniff` and a sandbox policy. Client filenames never form storage paths.
- Login attempts reserve capacity in MySQL transactions with row locks. Both case-normalized account and actual remote IP are limited to five attempts per 60 seconds, including successful attempts. Usernames and spoofed forwarding headers cannot bypass the IP bucket; concurrent workers share state. A 429 includes Retry-After. Expired buckets reset on reuse.
- CORS permits only configured exact origins and allowed methods/headers. Untrusted requests get no allow-origin header. CORS does not prevent a non-browser client from calling authenticated APIs.
- Unexpected fixed errors are logged server-side and return a generic response. Expected validation/conflict responses contain no SQL, stack traces, paths or configuration values.
- Gift messages remain plain text. Only the recipient/sender placeholders are replaced, once; user text is never compiled as Twig or PHP. The browser inserts the preview with `textContent`.
- Carrier requests accept only `http://delivery-service/tracking/` followed by a bounded uppercase tracking identifier. The exact URL format excludes credentials, alternate ports, queries, encoded paths and fragments. Redirects are disabled and non-200 responses rejected. Docker manages this trusted provider's DNS name. This policy intentionally allows the named internal carrier; it is not a general-purpose URL fetcher. Requests have a three-second timeout and a 64 KiB response cap.
- Help articles are selected from a fixed filename map. Upload folder labels are an enum and never become fixed storage paths. These controls block both the traversal write and the inclusion of any accepted upload.

## Deliberate lab limits

The browser stores JWTs in localStorage; a future session design could use HttpOnly cookies with CSRF protections. Logout deletes the client token but does not revoke issued JWTs before expiry. Seed passwords are published synthetic training credentials. The vulnerable app allows uploaded PHP execution and should never host real data or face an untrusted network.

The fixed throttle protects a small local lab. A shared NAT can consume one IP budget, and attackers can cause account denial of service. Trusted reverse proxy identity, abuse-aware policy, expired-bucket maintenance, monitoring and external secret storage are deployment work. Retaining attempted account buckets is bounded only by database capacity; this is not a general internet-scale rate limiter.

Image parsing uses the GD library supplied by the PHP image. Keep base images and dependencies updated. Encoding removes appended active content but does not prove an image parser cannot contain vulnerabilities. GIF animation is flattened during PNG conversion.

The API uses plain HTTP on loopback; TLS, security header policy for the full UI, audits, account recovery, email verification and production secret rotation are outside this lab. Bootstrap assets use a public CDN. No remote database ports are exposed; only the test runner joins both application networks. Each network has its own synthetic delivery service with no published port. Its internal dispatch endpoint contains only dummy data. Uploaded traversal markers under the vulnerable container's `public/drafts/` directory are ephemeral and disappear when that container is recreated.

## What tests establish

PHPUnit sends actual HTTP requests to Apache/PHP backed by MySQL. Paired tests cover all twelve scenarios and normal flows. Additional fixed tests cover signed malformed JWT claims/algorithms, concurrent throttling and expiry, password hashing, upload content and appended PHP removal, malformed JSON and role-input rejection. The added tests exercise template expression/control-flow evaluation, internal/loopback fetches, redirects, URL policy bypass attempts and uploaded PHP inclusion. Test infrastructure clears throttle buckets for deterministic tests and must be used only against this lab. HTTP JSON evidence shows observations; JUnit records assertion results.

Stored-XSS assertions verify raw versus encoded script markup in HTML, not browser execution. CORS tests verify preflight and response policy, not token theft. The harmless upload echo marker demonstrates local PHP execution without running OS commands. A weak-secret token with subject 4 proves impersonation; changing a role claim alone would not prove this because roles are loaded from the database.
